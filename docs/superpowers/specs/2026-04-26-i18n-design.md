## Android 13+ Per-App Language (SOTA)

### `res/xml/locale_config.xml`

Declares supported locales so the system's Settings → App language picker works without any in-app UI:

```xml
<?xml version="1.0" encoding="utf-8"?>
<locale-config xmlns:android="http://schemas.android.com/apk/res/android">
    <locale android:name="en"/>
    <locale android:name="es"/>
    <locale android:name="pt-BR"/>
    <locale android:name="ru"/>
    <locale android:name="ja"/>
    <locale android:name="hi"/>
    <locale android:name="de"/>
    <locale android:name="fr"/>
    <locale android:name="ko"/>
    <locale android:name="zh-Hans"/>
</locale-config>
```

### `AndroidManifest.xml` change

Add `android:localeConfig` to the `<application>` element:

```xml
<application
    ...
    android:localeConfig="@xml/locale_config">
```

This attribute is available from API 33. It is safe to add unconditionally — older APIs ignore it.

The success message in `PremiumCaptureRoute` contains two quantities. Use a regular format string (not `<plurals>`) since both counts appear in one sentence and plural rules differ across locales — translators will handle grammatical number within the translation itself:

## Compose Integration

### Static strings

```kotlin
// Before
Text(text = "Choose a handwriting style")
// After
Text(text = stringResource(R.string.template_chooser_title))
```

### Format strings inside composables

```kotlin
// Before
"Missing glyphs: ${missingCharacters.joinToString(" ")}"
// After
stringResource(R.string.render_missing_glyphs, missingCharacters.joinToString(" "))
```

### Strings set from coroutine/lambda scope (outside Compose tree)

`PremiumCaptureRoute` initialises `instructionText` via `rememberSaveable` and mutates it in coroutine callbacks. These use `context.getString()`:

```kotlin
val context = LocalContext.current
var instructionText by rememberSaveable {
    mutableStateOf(context.getString(R.string.premium_instruction))
}
// Inside coroutine callback:
instructionText = context.getString(R.string.premium_processing)
```

### Toast strings (non-composable lambdas)

`ResultPhaseContent` toast calls are inside `fun doSave()` / `fun exportPdf()` etc. which capture `context`:

```kotlin
fun doSave() {
    ...
    .onSuccess { toast(context.getString(R.string.result_saved)) }
    .onFailure { toast(context.getString(R.string.result_save_failed, it.message ?: "unknown")) }
}
```

### `LoadingTemplateScreen` call site

Currently `MainActivity` passes hardcoded string literals as parameters:
```kotlin
LoadingTemplateScreen(
    title = "Loading template",
    body = "Preparing bundled bitmap glyphs for the default handwriting flow.",
)
```
Switch to `stringResource()` at the call site (it is inside a composable):
```kotlin
LoadingTemplateScreen(
    title = stringResource(R.string.loading_template_title),
    body = stringResource(R.string.loading_template_body),
)
```

## What Does NOT Change

- `TemplateDescriptor.displayName`, `.description`, `.sampleText` — template metadata stays English
- `BundledTemplateRepository` — no changes
- All rendering / ML logic — no changes
- No new Gradle dependencies

---

## Out of Scope

- RTL layout mirroring (none of the 10 target locales are RTL)
- In-app language picker UI (system Settings handles this via `localeConfig.xml` on API 33+)
- App Store listing metadata translations (Play Console, separate process)
- Grammatical inflection API (Android 14+, not needed for these languages)
